# DeepAgent 多租户数据隔离设计文档

> 日期：2026-07-14
> 方案：无状态动态隔离（AgentScope 风格）
> 项目：agent-core-java

---

## 1. 背景与问题

当前 DeepAgent 框架在超级智能体场景中采用单例模型创建实体，并指定统一的 tmp 临时目录作为工作空间。该实现方式在多租户企业客户场景下存在数据隔离不足的问题：

1. 不同租户共享同一个实例工作空间及 tmp 临时目录，可能导致租户之间临时文件互相访问或写入干扰。
2. Skill 目录当前对所有请求上下文可见，无法基于租户粒度隔离不同租户可访问的数据。
3. 从智能体入口进入智能体后台后，系统当前只能感知不同 session，缺少基于租户 ID 的数据隔离能力。
4. 在企业多租户场景下，该问题可能导致不同租户之间发生数据越界访问，不满足客户合规要求。

---

## 2. 约束与边界

| 维度 | 约束 |
|------|------|
| 部署形态 | 单 JVM 进程，多个租户请求通过 HTTP/API 入口进入同一进程 |
| tenant_id 传递 | 当前无传递链路，需从入口层新增 |
| 数据存储 | 本地磁盘 + 部分外部存储（向量库 Milvus、检查点 Redis、skills/临时文件在本地） |
| 租户规模 | 100~1000 |
| 框架职责 | 仅根据 tenant_id 拉取已有租户数据或创建新租户数据空间 |
| 非框架职责 | 不做租户合法性校验，不感知个人/部门等业务概念 |
| 隔离对象 | 租户 skill 数据、租户临时生成文件、租户工作空间临时写入数据 |
| 非隔离对象 | 智能体配置文件、运行日志等公共运维类数据 |
| 向后兼容 | 多租户为增量能力，不改变现有单租户使用方式 |

---

## 3. 方案选型

### 3.1 三种方案对比

| 方案 | 核心思路 | 内存 | 并发 | 扩展性 | 改动量 |
|------|---------|------|------|--------|--------|
| A. 多实例隔离 | 每租户独立 ReActAgent 实例 + LRU 缓存 | O(N) | Semaphore 限制 | 差 | 小 |
| **B. 无状态动态隔离** | 单 DeepAgent 实例共享，每次调用动态注入租户隔离资源 | **O(1)** | **无限制** | **好** | **中** |
| C. 混合模式 | A+B 可切换，默认无状态 | — | — | — | 大 |

### 3.2 选择方案 B 的理由

1. **100~1000 租户**是方案 A 的瓶颈区间——多实例内存压力大，方案 B 单实例无状态天然适配。
2. **agent-core-java 已有 `sandboxRoot` + `restrictToSandbox` 机制**（见 `LocalWorkConfig`），天然支持租户目录隔离，只需动态绑定。
3. **核心改动点明确**：workspace 解析、sysop 配置、checkpointer key 前缀、skill 路径隔离，都是"注入不同配置"而非"重写逻辑"。
4. 方案 C 过度设计（YAGNI），当前阶段不必要。

## 4. 架构设计

### 4.1 整体架构

```
HTTP Request (header: X-Tenant-Id)
  │
  ▼
Controller 层
  │ 提取 X-Tenant-Id → 构建 TenantContext
  ▼
DeepAgent.invoke(inputs, session)
  │ session 已绑定 TenantContext
  ▼
┌─────────────────────────────────────────────────┐
│ 1. 提取 TenantContext → tenantId                 │
│ 2. TenantWorkspaceManager.initializeTenant()     │
│ 3. 构建隔离资源：                                 │
│    ├─ Workspace (tenants/{tenantId}/workspace)   │
│    ├─ SysOperation (sandboxRoot=租户目录)         │
│    ├─ Checkpointer (key前缀=tenantId:)           │
│    └─ SkillManager (全局+租户私有)               │
│ 4. TenantExecutionContext.set(ctx)  ← ThreadLocal│
│ 5. 执行 ReActAgent（不感知租户）                  │
│ 6. TenantExecutionContext.remove()  ← finally    │
└─────────────────────────────────────────────────┘
```

### 4.2 核心原则

- **ReActAgent 不感知租户**——隔离逻辑全部在 DeepAgent 层完成
- **每次调用独立上下文**——无共享可变状态，天然并发安全
- **TenantContext 驱动**——tenant_id 为空时降级为共享空间

## 5. 详细设计

### 5.1 tenant_id 传递链路

#### 传递路径

```
HTTP Request (header: X-Tenant-Id)
  → Controller 层提取 → TenantContext
    → Session 创建时绑定 TenantContext
      → SessionContextHolder 扩展（含 TenantContext）
        → DeepAgent.invoke() 从 Session 获取 TenantContext
          → 构建隔离资源，注入 TenantExecutionContext
            → ReActAgent 执行（使用已注入的隔离资源）
```

#### 核心类：TenantContext

```java
// com.openjiuwen.core.multitenant.TenantContext
@Data @Builder
public class TenantContext {
    private final String tenantId;
    private final Map<String, String> metadata;  // 框架不感知的业务字段，仅做透传
}
```

#### 改动点

| 文件 | 改动 |
|------|------|
| API Controller | 提取 `X-Tenant-Id` header，构建 TenantContext |
| `Session` 接口 | 新增 `getTenantContext()` 方法 |
| `SessionContextHolder` | 扩展携带 TenantContext |
| `AgentSessionApi` | 构造时绑定 TenantContext |

#### 边界

- 框架不做 tenant_id 合法性校验
- tenant_id 为 null/empty 时降级为默认共享空间

### 5.2 Workspace 隔离

#### 目录结构

```
{baseDataDir}/                          ← 由配置决定（如 /data/deepagent）
├── tenants/
│   └── {tenantId}/
│       ├── workspace/                  ← Workspace.rootPath
│       │   ├── memory/                ← MemoryRail 向量存储
│       │   ├── todo/                  ← Todo 数据
│       │   ├── skills/                ← 租户 Skill 目录
│       │   ├── agents/                ← 子 Agent
│       │   └── tmp/                   ← 临时文件
│       ├── checkpoints/               ← 检查点存储
│       └── .plans/                    ← 计划文件
├── shared/                             ← 全局共享（无 tenant_id 时降级）
│   ├── workspace/
│   └── ...
└── config/                             ← 智能体配置（不隔离）
```

#### 核心类：TenantWorkspaceManager

```java
// com.openjiuwen.core.multitenant.TenantWorkspaceManager
public class TenantWorkspaceManager {
    private final Path baseDataDir;
    private final Path sharedDir;

    /**
     * 解析租户 Workspace
     * - tenantId 非空 → 返回 tenants/{tenantId}/workspace
     * - tenantId 为空 → 返回 shared/workspace（向后兼容）
     */
    public Workspace resolveWorkspace(String tenantId) {
        Path root = tenantId != null && !tenantId.isBlank()
            ? baseDataDir.resolve("tenants").resolve(tenantId).resolve("workspace")
            : sharedDir.resolve("workspace");
        return Workspace.builder()
            .rootPath(root.toString())
            .language("cn")
            .build();
    }

    public Path resolveTmpDir(String tenantId) {
        return resolveWorkspace(tenantId).root().resolve("tmp");
    }

    /**
     * 初始化租户目录（并发安全，幂等）
     */
    public void initializeTenant(String tenantId) {
        if (tenantId == null || tenantId.isBlank()) {
            return;
        }
        Path tenantRoot = baseDataDir.resolve("tenants").resolve(tenantId);
        try {
            Files.createDirectories(tenantRoot.resolve("workspace").resolve("tmp"));
            Files.createDirectories(tenantRoot.resolve("workspace").resolve("skills"));
            Files.createDirectories(tenantRoot.resolve("checkpoints"));
        } catch (IOException e) {
            throw new IllegalStateException("Failed to initialize tenant directory: " + tenantId, e);
        }
    }
}
```

#### 路径安全防护

```java
// com.openjiuwen.core.multitenant.TenantPathValidator
public class TenantPathValidator {
    public static void validate(String tenantId, Path requestedPath) {
        if (tenantId == null || tenantId.isBlank()) {
            return;
        }
        Path tenantRoot = resolveTenantRoot(tenantId).normalize().toAbsolutePath();
        Path normalized = requestedPath.normalize().toAbsolutePath();
        if (!normalized.startsWith(tenantRoot)) {
            throw new SecurityException("Cross-tenant access denied: " + requestedPath);
        }
        // 额外检查软链接：解析符号链接后再次校验
        try {
            Path resolved = normalized.toRealPath();
            if (!resolved.startsWith(tenantRoot)) {
                throw new SecurityException("Cross-tenant symlink access denied: " + requestedPath);
            }
        } catch (IOException e) {
            throw new SecurityException("Path validation failed: " + requestedPath, e);
        }
    }
}
```

### 5.3 SysOperation 隔离

#### 核心思路

`LocalWorkConfig` 已有 `sandboxRoot` + `restrictToSandbox` 机制，每次 invoke 时动态构建租户隔离的 SysOperation。

#### 核心类：TenantSysOpFactory

```java
// com.openjiuwen.core.multitenant.TenantSysOpFactory
public class TenantSysOpFactory {
    private final TenantWorkspaceManager workspaceManager;

    public SysOperation createForTenant(String tenantId) {
        Path tenantRoot = workspaceManager.resolveWorkspace(tenantId).root();

        LocalWorkConfig config = LocalWorkConfig.builder()
            .workDir(tenantRoot.toString())
            .sandboxRoot(List.of(tenantRoot.toString()))
            .restrictToSandbox(true)
            .build();

        SysOperationCard card = SysOperationCard.builder()
            .id("sys_op_" + (tenantId != null ? tenantId : "shared"))
            .mode(OperationMode.LOCAL)
            .workConfig(config)
            .build();

        return new SysOperation(card);
    }
}
```

#### 隔离覆盖范围

| 操作 | 隔离方式 | 说明 |
|------|---------|------|
| 文件读写 | `sandboxRoot` + `restrictToSandbox` | 不可越出租户目录 |
| Shell 执行 | `workDir` 绑定租户目录 | Shell 工作目录在租户空间内 |
| 代码执行 | `workDir` 绑定租户目录 | 代码运行目录在租户空间内 |
| Skill 加载 | workspace 下 `skills/` 目录 | 仅加载租户 skills |

#### 额外安全措施

在 `LocalFsOperation` 关键方法中增加 sandbox 校验：

```java
private void assertWithinSandbox(Path path) {
    if (runConfig instanceof LocalWorkConfig cfg
        && cfg.isRestrictToSandbox()
        && cfg.getSandboxRoot() != null) {
        Path normalized = path.normalize().toAbsolutePath();
        boolean within = cfg.getSandboxRoot().stream()
            .anyMatch(root -> normalized.startsWith(Path.of(root).normalize().toAbsolutePath()));
        if (!within) {
            throw ErrorHelper.fail(StatusCode.PERMISSION_DENIED,
                "Path escapes sandbox: " + path);
        }
    }
}
```

#### SANDBOX 模式隔离

当 `DeepAgentConfig` 配置为 `OperationMode.SANDBOX` 时，`TenantSysOpFactory` 同样需要为租户生成隔离的 SysOperation。Sandbox 模式通过 `SandboxGatewayConfig` 的 `isolationKey` 实现隔离，不同租户使用不同的 isolationKey 确保远端容器隔离。

```java
// TenantSysOpFactory 中 SANDBOX 模式分支
private SysOperation createSandboxForTenant(String tenantId, SandboxGatewayConfig baseConfig) {
    // 为租户生成唯一的 isolationKey
    String isolationKey = tenantId != null && !tenantId.isBlank()
        ? tenantId + "_" + baseConfig.getIsolationKey()
        : baseConfig.getIsolationKey();

    SandboxGatewayConfig tenantConfig = SandboxGatewayConfig.builder()
        .gatewayUrl(baseConfig.getGatewayUrl())
        .isolationKey(isolationKey)
        .params(baseConfig.getParams())
        .build();

    SysOperationCard card = SysOperationCard.builder()
        .id("sys_op_" + (tenantId != null ? tenantId : "shared"))
        .mode(OperationMode.SANDBOX)
        .gatewayConfig(tenantConfig)
        .build();

    return new SysOperation(card);
}
```

**隔离效果**：每个租户在远端 sandbox 中拥有独立的容器/工作空间，通过 isolationKey 路由到对应容器。

#### 边界

- LOCAL 和 SANDBOX 两种模式均支持租户隔离
- 不改变 `SysOperation` 类本身，仅通过不同配置实现隔离
- tenantId 为空时降级为无隔离约束的默认 SysOperation

### 5.4 Checkpointer 隔离

#### 核心类：TenantCheckpointerFactory

```java
// com.openjiuwen.core.multitenant.TenantCheckpointerFactory
public class TenantCheckpointerFactory {
    private final CheckpointerFactory delegate;

    /**
     * 为租户创建隔离的 Checkpointer
     * Redis key 格式：deepagent:{tenantId}:{sessionId}
     * 无 tenantId 时：deepagent:{sessionId}（向后兼容）
     */
    public Checkpointer createForTenant(String tenantId, String sessionId) {
        String effectiveSessionId = tenantId != null && !tenantId.isBlank()
            ? tenantId + ":" + sessionId
            : sessionId;
        return delegate.create(effectiveSessionId);
    }
}
```

#### 隔离效果

```
租户 A: deepagent:company-a:sess-123  → 只能读写自己的检查点
租户 B: deepagent:company-b:sess-123  → 只能读写自己的检查点
共享:   deepagent:sess-123             → 无租户时降级
```

### 5.5 Skill 隔离

#### 核心类：TenantSkillManager

```java
// com.openjiuwen.core.multitenant.TenantSkillManager
public class TenantSkillManager {
    private final SkillManager globalSkillManager;
    private final TenantWorkspaceManager workspaceManager;

    /**
     * 获取租户可访问的 skill 列表
     * 合并：全局公共 skills + 租户私有 skills
     */
    public List<Skill> listSkills(String tenantId, String sessionId) {
        List<Skill> skills = new ArrayList<>(globalSkillManager.listSkills(sessionId));

        Path tenantSkillDir = workspaceManager.resolveWorkspace(tenantId)
            .root().resolve("skills");
        if (Files.isDirectory(tenantSkillDir)) {
            SkillManager tenantMgr = new SkillManager("sys_op_" + tenantId);
            tenantMgr.register(tenantSkillDir.toString(), sessionId, false);
            skills.addAll(tenantMgr.listSkills(sessionId));
        }
        return skills;
    }
}
```

#### Skill 目录结构

```
tenants/{tenantId}/workspace/skills/    ← 租户私有 skills
shared/workspace/skills/                 ← 全局公共 skills
{agent-config-dir}/skills/               ← 智能体配置级 skills（不隔离）
```

### 5.6 并发安全

| 场景 | 方案 |
|------|------|
| 多请求同时初始化同一租户 | `Files.createDirectories` 天然幂等 |
| 同一租户并发写入 | 依赖底层存储并发控制（Redis 天然支持；本地文件由 OS 文件锁保证） |
| TenantExecutionContext 跨线程 | TaskLoop 内部线程启动时继承上下文，结束时清理 |
| SysOperation 并发使用 | 每次 invoke 创建独立实例，无共享可变状态 |

    private final SysOperation sysOperation;

    public static void set(TenantExecutionContext ctx) { HOLDER.set(ctx); }

}

## 6. DeepAgent.invoke() 整体流程

```java
public Map<String, Object> invoke(Map<String, Object> inputs, AgentSessionApi session) {
    // 1. 提取租户上下文
    TenantContext tenantCtx = session.getTenantContext();
    String tenantId = tenantCtx != null ? tenantCtx.getTenantId() : null;

    // 2. 初始化租户目录（幂等）
    tenantWorkspaceManager.initializeTenant(tenantId);

    // 3. 构建隔离资源
    Workspace tenantWorkspace = tenantWorkspaceManager.resolveWorkspace(tenantId);
    SysOperation tenantSysOp = tenantSysOpFactory.createForTenant(tenantId);
    Checkpointer tenantCp = tenantCheckpointerFactory.createForTenant(
        tenantId, sessionId);

    // 4. 注入到执行上下文（ThreadLocal）
    TenantExecutionContext ctx = TenantExecutionContext.builder()
        .tenantId(tenantId)
        .workspace(tenantWorkspace)
        .sysOperation(tenantSysOp)
        .checkpointer(tenantCp)
        .build();
    TenantExecutionContext.set(ctx);

    try {
        // 5. 执行（ReActAgent 不感知租户，使用注入的资源）
        return doInvoke(inputs, session);
    } finally {
        // 6. 清理 ThreadLocal，防止泄漏
        TenantExecutionContext.remove();
    }
}
```

## 9. 验收标准

1. 不同租户 ID 之间无法访问彼此的 skill 数据
2. 不同租户 ID 之间无法访问彼此临时生成的文件
3. 不同租户 ID 之间的临时写入不会互相影响
4. 请求携带已有租户 ID 时，deepagent 能正确加载该租户对应的数据空间
5. 请求携带新的租户 ID 且对应数据不存在时，deepagent 能创建新的租户数据空间
6. 不能通过路径拼接、相对路径、软链接等方式访问其他租户的数据目录
7. agent 框架不依赖个人、部门等业务字段即可完成租户数据隔离
8. 不携带 tenant_id 的请求行为与改造前一致（向后兼容）

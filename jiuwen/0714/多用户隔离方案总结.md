# DeepAgentExample 多用户数据隔离方案总结

## 方案概览

本方案为 DeepAgentExample 实现了完整的**多用户数据隔离**能力，支持两种架构模式：

| 模式 | 特点 | 适用场景 |
|------|------|----------|
| **多实例隔离** | 每个租户独立 DeepAgent 实例 | 资源充足、高隔离要求 |
| **单实例动态 Workspace** | 共享 Agent，workspace 外部存储动态加载 | Serverless、弹性伸缩、大规模 |

## 核心隔离维度

### 1. 租户级隔离

**实现方式**: `TenantAgentManager` 按 `tenantId + userId` 维护独立的 `DeepAgent` 实例

```java
TenantContext ctx = TenantContext.builder()
    .tenantId("company-a")
    .userId("alice")
    .build();

DeepAgent agent = TenantAgentManager.getInstance().getOrCreateAgent(ctx);
```

**隔离效果**:
- 每个租户独立的 JVM 对象
- 独立的 Workspace 目录
- 独立的 SysOperation 沙箱
- 独立的检查点 key 前缀

### 2. 磁盘目录隔离

**目录结构**:
```
~/.deepagent-demo/
  tenant_{tenantId}/
    user_{userId}/
      ├── workspace/          # DeepAgent Workspace
      │   ├── memory/        # MemoryRail 向量存储
      │   ├── todo/          # Todo 数据
      │   ├── skills/        # 用户级 Skills
      │   └── agents/        # 子 Agent
      ├── checkpoints/       # 检查点（SQLite/Redis）
      ├── config/            # 租户配置
      └── logs/              # 租户级日志
```

**实现方式**: `TenantWorkspace.initializeWorkspace(ctx)`

### 3. 会话隔离

**实现方式**: `conversation_id` 区分不同会话

```java
String sessionId = ctx.getConversationId("session-1");
agent.run(Map.of(
    "query", query,
    "conversation_id", sessionId
));
```

### 4. Redis 检查点隔离

**Key 前缀**: `deepagent:{tenantId}:{userId}:`

```
完整 key: deepagent:company-a:alice:session-123
```

**实现方式**: `TenantCheckpointerSupport.buildTenantRedisConfig(ctx)`

### 5. 工具权限隔离

**白名单模式**:
```java
TenantPermissionRail.whitelist(ctx, Set.of("read_file", "search"));
```

**黑名单模式**:
```java
TenantPermissionRail.blacklist(ctx, Set.of("bash", "exec_command"));
```

│     │ (load)   │ │ (load)   │ │ (load)   │                     │
│     └─────┬────┘ └─────┬────┘ └─────┬────┘                     │
│           │            │            │                          │

            │            │            │

### 执行流程

```
用户请求
    │
    ▼
┌──────────────────┐
│ 1. 获取并发许可   │◄── Semaphore 控制
│    (Semaphore)   │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ 2. 加载 Workspace │◄── 从 OBS/HDFS 下载
│    (Provider)    │    解压到本地临时目录
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ 3. 绑定 Workspace │◄── ThreadLocal 绑定
│    (Context)     │    更新 Agent workspace 引用
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ 4. 执行 Agent     │◄── 使用用户专属 workspace
│    (DeepAgent)   │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ 5. 保存 Workspace │◄── 压缩/同步回外部存储
│    (Provider)    │    更新版本号
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ 6. 解绑 Workspace │◄── ThreadLocal 清理
│    (Context)     │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ 7. 清理临时文件   │◄── 根据缓存策略决定
│    (Cleanup)     │    LRU / 立即清理 / 会话保持
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ 8. 释放并发许可   │◄── Semaphore 释放
│    (Release)     │
└──────────────────┘
```

## 部署模式对比

### 模式 1: 单机多租户（TenantAgentManager）

```
┌─────────────────────────────────────────┐
│  Single JVM Process                      │
│  ┌───────────────────────────────────┐ │
│  │ TenantAgentManager                 │ │
│  │  ┌─────┐ ┌─────┐ ┌─────┐         │ │
│  │  │Agent│ │Agent│ │Agent│ ...      │ │
│  │  │ A   │ │ B   │ │ C   │          │ │
│  │  └─────┘ └─────┘ └─────┘          │ │
│  │  LRU Cache (max=100, TTL=30min)   │ │
│  └───────────────────────────────────┘ │
└─────────────────────────────────────────┘
           │
    ┌──────┴──────┐
    ▼             ▼
┌────────┐   ┌────────┐
│ Redis  │   │ 本地   │
│(检查点) │   │ 磁盘   │
└────────┘   └────────┘
```

**特点**:
- 每个租户独立 DeepAgent 实例
- 内存占用较高
- 实现简单，隔离性强
- 适合中小规模（<100 租户）

### 模式 2: 共享实例 + 外部存储（SharedAgentManager）

```
┌─────────────────────────────────────────┐
│  Single JVM Process                      │
│  ┌───────────────────────────────────┐ │
│  │ SharedAgentManager                 │ │
│  │  ┌─────────────────────────────┐ │ │
│  │  │ 1 DeepAgent Instance        │ │ │
│  │  │ (dynamic workspace)         │ │ │
│  │  └─────────────────────────────┘ │ │
│  │  Semaphore (concurrent=50)      │ │
│  └───────────────────────────────────┘ │
└─────────────────────────────────────────┘
           │
    ┌──────┴──────┬──────────┐
    ▼             ▼          ▼
┌────────┐  ┌────────┐  ┌────────┐
│  OBS   │  │ Redis  │  │ Milvus │
│(Workspace│  │(检查点) │  │(向量库) │
└────────┘  └────────┘  └────────┘
```

**特点**:
- 单 Agent 实例服务多用户
- workspace 按需从外部存储加载
- 内存占用低
- 并发受限（Semaphore 控制）
- 适合 Serverless/弹性伸缩

### 模式 3: 连接池模式

```
┌─────────────────────────────────────────┐
│  Agent Connection Pool (N instances)      │
│  ┌─────┐ ┌─────┐ ┌─────┐     ┌─────┐   │
│  │Ag-1 │ │Ag-2 │ │Ag-3 │ ... │Ag-N │   │
│  └─────┘ └─────┘ └─────┘     └─────┘   │
│  负载均衡调度                            │
└─────────────────────────────────────────┘
```

**特点**:
- N 个 Agent 实例共享工作
- 连接池调度分配请求
- 支持更高并发
- 需要额外调度逻辑

### 模式 4: Serverless 函数

```
Request ──► API Gateway ──► Function Container
                              ┌───────────────┐
                              │ 冷启动        │
                              │ 1. 加载代码   │
                              │ 2. 初始化 Agent│
                              │ 3. 加载 workspace
                              │ 4. 执行请求   │
                              │ 5. 保存 workspace
                              │ 6. 容器销毁   │
                              └───────────────┘
                                    │
                                    ▼
                              ┌───────────────┐
                              │ OBS / S3      │
                              │ (workspace)   │
                              └───────────────┘
```

**特点**:
- 按需启动，按量付费
- 无状态设计，完全隔离
- 冷启动延迟（1-5 秒）
- 适合突发流量

## 性能优化建议

### 1. 本地缓存

使用 `LocalCacheWorkspaceProvider` 缓存热点用户 workspace：

```java
LocalCacheWorkspaceProvider cachedProvider = new LocalCacheWorkspaceProvider(
    obsProvider,
    100,    // 缓存 100 个 workspace
    30,     // 30 分钟空闲过期
    true    // 启用增量同步
);
```

### 2. 预加载

启动时预加载活跃用户 workspace：

```java
@Component
public class WorkspacePreloader {
    @Scheduled(fixedRate = 60000)
    public void preloadActiveSessions() {
        List<SessionInfo> activeSessions = getActiveSessions();
        for (SessionInfo session : activeSessions) {
            provider.loadWorkspace(...);  // 预加载
        }
    }
}
```

### 3. 向量数据库外部化

将 MemoryRail 的向量存储从本地文件迁移到 Milvus/Pinecone：

```java
public class ExternalVectorMemory implements MemoryStore {
    private final MilvusClient milvus;
    
    public void save(Memory memory, String tenant, String user) {
        milvus.upsert(
            buildCollectionName(tenant, user),  // tenant_user_memory
            memory
        );
    }
}
```

### 4. 并发控制

根据负载调整并发限制：

```java
SharedAgentManager manager = SharedAgentManager.builder()
    .concurrentLimit(50)      // 根据 CPU/内存调整
    .requestTimeoutMs(60000)    // 60 秒超时
    .build();
```

## 安全加固

### 1. 数据加密

```java
public class EncryptedWorkspaceProvider implements WorkspaceProvider {
    private final byte[] getTenantKey(String tenantId) {
        // 从 KMS 获取租户级密钥
        return kmsClient.getDataKey(tenantId);
    }
    
    public Path loadWorkspace(...) {
        Path encrypted = delegate.loadWorkspace(...);
        return encryption.decrypt(encrypted, getTenantKey(tenantId));
    }
}
```

### 2. 访问审计

```java
public class AuditingWorkspaceProvider implements WorkspaceProvider {
    public Path loadWorkspace(...) {
        auditLogger.log(AuditEvent.builder()
            .action("WORKSPACE_LOAD")
            .tenantId(tenantId)
            .userId(userId)
            .timestamp(Instant.now())
            .build());
        return delegate.loadWorkspace(tenantId, userId, sessionId);
    }
}
```

### 3. 跨租户防护

```java
public class TenantIsolationValidator {
    public void validate(String currentTenant, Path requestedPath) {
        if (!requestedPath.toString().contains("/tenants/" + currentTenant + "/")) {
            throw new SecurityException("Cross-tenant access detected!");
        }
    }
}
```

## 监控指标

建议监控的关键指标：

| 指标 | 说明 | 告警阈值 |
|------|------|---------|
| `tenant.agent.cache.size` | 缓存 Agent 数 | > 80% max |
| `tenant.agent.cache.hit_rate` | 缓存命中率 | < 50% |
| `workspace.load.duration` | Workspace 加载耗时 | > 500ms |
| `workspace.save.duration` | Workspace 保存耗时 | > 1s |
| `shared.agent.concurrent` | 当前并发数 | > 80% limit |
| `shared.agent.queue.length` | 等待队列长度 | > 10 |

## 总结

本方案为 DeepAgentExample 提供了完整的企业级多用户数据隔离能力：

1. **多实例模式** (`TenantAgentManager`): 每个租户独立 DeepAgent，简单可靠，适合中小规模
2. **共享实例模式** (`SharedAgentManager`): 单实例服务多用户，workspace 外部存储动态加载，适合大规模/Serverless
3. **可扩展架构**: `WorkspaceProvider` 接口支持任意外部存储（OBS、HDFS、S3）
4. **完整演示**: 提供 3 个演示文件，覆盖基础使用、隔离验证、动态加载场景

# 多租户数据隔离功能 — 全生命周期总结

> 本文档记录 Java 版 openJiuwen 多租户数据隔离功能从设计、计划、开发、调试、测试到影响的完整过程，用于后期维护参考。

---

## 1. 需求背景

企业级 SaaS 平台需要支持多租户数据隔离，确保不同租户（部门、组织、个人等）之间的 skill 数据、临时文件、workspace 写入、Checkpointer 状态和 LongTermMemory 数据互不可见。同时保证不传 tenantId 时行为与现有一致，零迁移风险。

---

## 2. 设计阶段

### 2.1 设计规格文档

- 文档路径：`yoskills/jiuwen/0713/多租户数据隔离设计规格.md`
- 核心设计原则：
  1. **不透明标识符**：tenantId 是业务方定义的不透明标识符，框架不赋予业务语义
  2. **完全向后兼容**：不传 tenantId 时行为与现有一致，零迁移风险
  3. **框架不校验**：不负责租户合法性校验，不判断用户是否属于某个租户
  4. **安全纵深防御**：三层路径安全防护（字符规范化 + 路径穿越校验 + 软链接解析）
  5. **并发安全**：ConcurrentHashMap.computeIfAbsent 防冲突
  6. **YAGNI**：核心隔离层优先，高级抽象按需引入

### 2.2 需隔离资源范围

| 资源 | 需隔离 | 说明 |
|------|--------|------|
| Skill 数据 | ✅ | 租户私有 skill 对其他租户不可见 |
| 临时文件 | ✅ | tmp 目录按租户隔离 |
| Workspace 写入 | ✅ | workspace 目录按租户隔离 |
| Checkpointer 状态 | ✅ | KV key 按 tenantId 前缀隔离 |
| LongTermMemory | ✅ | 所有 memory KV key 按 tenantId 前缀隔离 |
| 团队/个人记忆 | ✅ | scopeId 包含 tenantId |
| 共享文件操作 | ✅ | LocalFsOperation 校验租户边界 |
| 智能体配置文件 | ❌ | 全局共享 |
| 运行日志 | ❌ | 全局共享 |
| ResourceMgr | ❌ | 全局共享 |
| MessageQueue | ❌ | 全局共享 |
| CallbackFramework | ❌ | 全局共享 |
| VectorStore | ❌ 当前不隔离 | Phase 5+ |
| BaseDbStore (SQL) | ❌ 当前不隔离 | Phase 5+ |

## 4. 调试阶段

### 4.1 编译歧义问题

**问题**：`invoke(inputs, null)` 同时匹配 `TenantContext` 和 `AgentSessionApi` 两个重载，导致编译失败。

**修复过程**：
1. 首先用 `(AgentSessionApi) null` 显式类型转换临时解决（Commit `00602650`）
2. Phase 5 最终方案消除歧义：删除 `invoke(inputs, session, TenantContext)` 组合重载，`invoke(inputs, session)` 从 session 自动提取 tenantContext

### 4.2 ST 测试修复

**问题 1**：AgentCard 缺少 id 字段，ResourceMgr 校验报错 `agent id is invalid`

**修复**：AgentCard.builder() 增加 `.id(agentId)` 字段

**问题 2**：tenant workspace 路径断言不匹配实际目录结构

**修复**：测试断言从 `tenants/tenant_a/workspace` 改为 `tenant_a/tenants/tenant_a/workspace`（TenantNamespaceFactories.PATH_DEFAULT 的两层命名）

**问题 3**：apiconfig.json 包含真实 API 信息

**修复**：通过 `git rebase -i` 重写历史，替换为占位符值，`git reflog expire --expire=now --all` + `git gc --prune=now` 清除 dangling objects

## 9. 快速参考

### 9.1 如何使用多租户数据隔离

```java
// 推荐：通过 AgentSessionApi 传入
TenantContext ctx = TenantContext.builder().tenantId("my_dept").build();
AgentSessionApi session = new AgentSessionApi("session-1").withTenantContext(ctx);
Map<String, Object> result = deepAgent.invoke(inputs, session);

// 替代：快捷入口（无 session）
Map<String, Object> result = deepAgent.invoke(inputs, ctx);
```

### 9.2 如何自定义命名空间策略

```java
TenantNamespaceFactory customFactory = (tenantCtx, rawKey) -> {
    if (tenantCtx != null && tenantCtx.isTenantAware()) {
        return "biz_" + tenantCtx.safeTenantId() + "|" + rawKey;
    }
    return rawKey;
};
TenantKVStoreKeyResolver.setGlobalNamespaceFactory(customFactory);
```

### 9.3 如何添加远程存储后端

```java
WorkspaceStoreFactory.register("my_tier", new MyStoreProvider());
DeepAgentConfig config = DeepAgentConfig.builder()
    .workspaceSecondaryTiers(List.of("obs", "my_tier"))
    .workspaceTierConfigs(Map.of("my_tier", Map.of("host", "my-host")))
    .build();
```

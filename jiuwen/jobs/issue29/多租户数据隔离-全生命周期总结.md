# 多租户数据隔离功能 — 全生命周期总结

> 本文档记录 Java 版 openJiuwen 多租户数据隔离功能从设计、计划、开发、调试、测试到影响的完整过程，用于后期维护参考。

---

## 1. 需求背景

企业级 SaaS 平台需要支持多租户数据隔离，确保不同租户（部门、组织、个人等）之间的 skill 数据、临时文件、workspace 写入、Checkpointer 状态和 LongTermMemory 数据互不可见。同时保证不传 tenantId 时行为与现有一致，零迁移风险。

---

## 2. 设计阶段

### 2.1 设计规格文档

- 文档路径：`d:\jiuwen\main\yoskills\jiuwen\0713\多租户数据隔离设计规格.md`
- 设计原则：
  1. **不透明标识符**：tenantId 是业务方定义的不透明标识符，框架不赋予业务语义
  2. **完全向后兼容**：不传 tenantId 时行为与现有一致
  3. **框架不校验**：不负责租户合法性校验
  4. **安全纵深防御**：三层路径安全防护
  5. **并发安全**：ConcurrentHashMap.computeIfAbsent 防冲突
  6. **YAGNI**：核心隔离层优先，高级抽象按需引入

### 2.2 分阶段规划

| Phase | 目标 | 状态 |
|-------|------|------|
| Phase 1 | 核心隔离层：TenantContext/TenantContextHolder/TenantWorkspaceResolver/TenantPathSecurity/TenantKVStoreKeyResolver + 全组件适配 | ✅ 已完成 |
| Phase 2 | Runner 层整合：RunnerConfig/RunnerImpl/AgentAdapter/CLI 传递 tenantId | ✅ 已完成 |
| Phase 3 | TenantNamespaceFactory 抽象：函数式接口 + 各组件使用 NamespaceFactory | ✅ 已完成 |
| Phase 4 | TieredWorkspaceManager 分层路由：本地 + OBS/S3/HDFS 远程存储 | ✅ 已完成 |
| Phase 5 | TenantContext 封装到 AgentSessionApi，消除冗余方法重载 | ✅ 已完成 |

## 4. 调试阶段

### 4.1 编译歧义问题

- 问题：`invoke(inputs, null)` 同时匹配 `TenantContext` 和 `AgentSessionApi` 两个重载
- 修复：改为 `invoke(inputs, (AgentSessionApi) null)` 明确类型
- Phase 5 后彻底解决：删除了 session+TenantContext 组合重载

### 4.2 ST 测试路径断言不匹配

- 问题：TenantWorkspaceResolver 使用 PATH_DEFAULT factory，生成 `tenantId/tenants/tenantId/workspace` 路径结构，ST 断言写的是 `tenants/tenantId/workspace`
- 修复：调整断言路径为 `tenantId/tenants/tenantId/workspace`

### 4.3 ST agent id 验证失败

- 问题：AgentCard.builder().name(agentId) 只设了 name 没设 id，ResourceMgr.addAgent 校验 id 不能为空
- 修复：改为 AgentCard.builder().id(agentId).name(agentId)

### 4.4 apiconfig.json 真实信息泄露

- 问题：git 历史中包含真实 API_BASE（IP 地址）和 API_KEY
- 修复：git rebase 修改 dc7daba0 commit，替换为占位符值；git reflog expire + gc --prune=now 清除 dangling objects

## 9. 关键架构决策记录

| 决策 | 选项 | 最终选择 | 理由 |
|------|------|----------|------|
| TenantContext 传递方式 | A: 独立方法参数 / B: 封装到 inputs Map / C: 封装到 AgentSessionApi + 保留快捷入口 | C | 消除冗余重载、解决编译歧义、类型安全、保留简单场景快捷入口 |
| 命名空间策略 | 硬编码 `tenantId:` / 可配置 TenantNamespaceFactory | TenantNamespaceFactory | 支持自定义分隔符/前缀/OBS bucket 映射等高级场景 |
| 工作空间存储 | 仅本地 / 分层本地+远程 | TieredWorkspaceManager | 企业场景需要本地+远程多级存储 |
| Runner 层简化 | 删除所有 TenantContext 重载 / 保留 + resolveTenantContext | 保留 + resolveTenantContext | Runner 用 Object session 无法直接利用 AgentSessionApi.tenantContext，保留重载作为快捷入口 |

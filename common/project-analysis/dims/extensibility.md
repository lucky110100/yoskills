# 可扩展性 — 维度分析卡（stub）

> 维度归属：D 演进质量组。评估扩展点、插件机制、接口抽象、配置驱动。**对标要点待阶段 2 补全。**

## 评估信号（发现即记）

- 无扩展点/硬编码分支（if-else 满天飞）
- 紧耦合难扩展（改一处动多处）
- 无插件/钩子机制
- 配置硬编码
- 接口无抽象（直接依赖实现类）

## 评估工具与命令

| 工具 | 命令/用法 | 看什么 |
|------|----------|--------|
| Grep | 查插件/钩子/SPI（@SPI/plugin/register） | 扩展机制存在性 |
| ast-grep | if-else 分支密度 | 硬编码分支热点 |
| Grep | 查 interface/abstract | 抽象程度 |
| Grep | 查配置注入（@Value/@Config） | 配置驱动程度 |

## 评分锚点（5 档）

| 分 | 锚点信号 |
|----|---------|
| 4 | 明确扩展点 + 插件机制 + 接口抽象 + 配置驱动 + 扩展文档 |
| 3 | 有部分扩展点 + 接口抽象 |
| 2 | 少量扩展点 + 部分硬编码分支 |
| 1 | 无扩展点 + 大量 if-else |
| 0 | 完全硬编码，无法扩展 |

## 规范基线

- ✅ 应：明确扩展点 + 插件/SPI 机制 + 面向接口 + 配置驱动 + 扩展文档
- ❌ 不做：硬编码 if-else 分支 + 直接依赖实现类 + 改一处动多处

## 对标要点（业界标杆看哪些）

- Java: 看 Spring Boot 的 `autoconfigure/`(条件装配扩展点)、RuoYi-Vue-Plus 的模块化拆分
- Python: 看 FastAPI 的依赖注入、Django 的 `contrib/` 可插拔、LangChain 的 agents/tools 抽象
- 对比扩展点明确度与插件机制成熟度

## 反模式

```
❌ if-else 堆叠变体（应改策略/插件模式）
❌ 直接依赖实现类（无法替换）
❌ 扩展点无文档（用户不知能扩展）
```

## Checklist

- [ ] 是否有扩展点/插件机制
- [ ] 是否面向接口
- [ ] if-else 分支是否过多
- [ ] 是否配置驱动

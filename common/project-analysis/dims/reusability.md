# 复用性 — 维度分析卡（stub）

> 维度归属：B 代码质量组。评估重复代码、公共模块清晰度、抽象恰当性。**对标要点待阶段 2 补全。**

## 评估信号（发现即记）

- 重复代码（copy-paste 块）
- 公共模块缺失或散落各处
- 过度抽象（为复用而抽象，实际只用一处）
- 循环依赖阻碍复用
- 常量/配置散布多处

## 评估工具与命令

| 工具 | 命令/用法 | 看什么 |
|------|----------|--------|
| jscpd/duplicate-finder | 重复代码扫描 | 重复率与热点 |
| ast-grep | 相似模式 | 可抽取的公共逻辑 |
| Grep | 重复常量/字符串 | 散布程度 |
| madge/dependency-cruiser | 依赖图 | 循环/孤立阻碍复用 |

## 评分锚点（5 档）

| 分 | 锚点信号 |
|----|---------|
| 4 | 无重复(jscpd<1%) + 公共模块清晰 + 抽象恰当 + 复用有文档 |
| 3 | 偶有重复 + 公共模块基本清晰 |
| 2 | 多处重复 + 公共模块零散 |
| 1 | 大量重复 + 无公共抽象 |
| 0 | 全是 copy-paste，无任何复用设计 |

## 规范基线

- ✅ 应：建公共模块 + 用 jscpd CI 门禁 + 抽象前先有三处复用例( Rule of Three) + 复用文档
- ❌ 不做：过早抽象 + copy-paste 不抽取 + 公共模块职责不清

## 对标要点（业界标杆看哪些）

- Java: 看 mall 的 `mall-common/` 公共模块、RuoYi-Vue-Plus 的 `ruoyi-common/`(脱敏/翻译/多租户抽取)
- Python: 看 Django 的 `django/contrib/` 可插拔应用、requests 的通用 API 封装
- 对比公共模块职责边界与抽取时机(Rule of Three: 三处复用才抽象)

## 反模式

```
❌ 过早抽象（实际只用一处）
❌ copy-paste 不抽取（债务累积）
❌ 公共模块"什么都放"（职责不清）
```

## Checklist

- [ ] 是否扫了重复代码
- [ ] 公共模块是否清晰
- [ ] 是否过度抽象
- [ ] 循环依赖是否阻碍复用

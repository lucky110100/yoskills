# 可靠性 — 维度分析卡（否决项·stub）

> 维度归属：C 运行时质量组。**否决项：本维度=0 即整体计 1 否决。** 评估容错、重试、熔断、限流、幂等、异常处理。**对标要点待阶段 2 补全。**

## 评估信号（发现即记）

- 无重试/超时/熔断
- 异常被吞（空 catch）
- 无幂等设计
- 无限流/背压
- 数据一致性无保障

## 评估工具与命令

| 工具 | 命令/用法 | 看什么 |
|------|----------|--------|
| Grep | 查重试/熔断/限流库（resilience4j/hystrix/sentinel） | 容错设施 |
| Grep | 查空 catch（`catch.*\{\s*\}`） | 异常吞没 |
| RunCommand | 混沌测试（chaos-mesh 等） | 容错验证 |
| Grep | 查事务/幂等实现 | 一致性保障 |

## 评分锚点（5 档）

| 分 | 锚点信号 |
|----|---------|
| 4 | 重试+超时+熔断+限流+幂等+混沌测试+异常分类处理 |
| 3 | 有重试/超时 + 偶有异常吞 |
| 2 | 部分容错 + 异常处理不全 |
| 1 | 异常常被吞 + 无容错 |
| 0 | 无容错/异常全吞（触发否决） |

## 规范基线

- ✅ 应：重试+超时+熔断+限流+幂等+异常分类+混沌测试
- ❌ 不做：空 catch + 无超时的外部调用 + 非幂等的关键写操作

## 对标要点（业界标杆看哪些）

- Java: 看 Spring Cloud Alibaba 的 Sentinel(限流/熔断/降级)与 Seata(分布式事务)
- Python: 看 Celery 的 `celery/app/trace.py` 任务重试/追踪
- 对比重试/超时/熔断/幂等的具体实现模式

## 反模式

```
❌ 空 catch 吞异常（静默失败）
❌ 外部调用无超时（拖垮整体）
❌ 关键写操作非幂等（重试致脏数据）
```

## Checklist

- [ ] 是否有重试/超时/熔断
- [ ] 是否有空 catch
- [ ] 关键写操作是否幂等
- [ ] 是否有限流/背压

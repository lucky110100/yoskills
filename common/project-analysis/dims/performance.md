# 性能 — 维度分析卡（stub）

> 维度归属：C 运行时质量组。评估 N+1、循环重操作、缓存、压测基线。**对标要点待阶段 2 补全。**

## 评估信号（发现即记）

- N+1 查询（循环内查库）
- 循环内重操作/IO
- 无缓存或重复计算
- 大对象/潜在内存泄漏
- 无性能基准/压测

## 评估工具与命令

| 工具 | 命令/用法 | 看什么 |
|------|----------|--------|
| RunCommand | 跑压测（wrk/locust/k6） | 吞吐/延迟/瓶颈 |
| Grep | 查慢日志/慢 SQL | 慢点 |
| radon/lizard | 复杂度热点 | 关联性能的热点函数 |
| Glob | 查性能基准测试文件 | 基线存在性 |

## 评分锚点（5 档）

| 分 | 锚点信号 |
|----|---------|
| 4 | 有性能预算 + 压测基线 + 无 N+1 + 缓存得当 + 性能基准 CI |
| 3 | 偶有 N+1 + 有部分压测 |
| 2 | 多处 N+1/循环重操作 + 无压测 |
| 1 | 明显性能问题 + 无任何性能考量 |
| 0 | 严重性能问题（如全表扫描频繁） |

## 规范基线

- ✅ 应：性能预算 + 压测基线 + 缓存策略 + N+1 检测 + 性能基准 CI
- ❌ 不做：循环内查库 + 无压测就上线 + 盲目加缓存

## 对标要点（业界标杆看哪些）

- Java: 看 Spring Boot 的 actuator 性能指标、Spring Cloud Alibaba 的 Sentinel 流控
- Python: 看 Pydantic 的 `pydantic-core/` Rust 内核(性能范本)、Celery 的并发策略
- 对比性能预算设定与基准测试存在性

## 反模式

```
❌ 循环内查库（N+1）
❌ 无压测基线就优化（盲目）
❌ 缓存无策略（一致性/失效无设计）
```

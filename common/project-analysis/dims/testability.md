# 可测试性 — 维度分析卡（否决项）

> 维度归属：B 代码质量组。**否决项：本维度=0 即整体计 1 否决。** 评估测试分层、依赖注入、覆盖率、测试速度、外部依赖隔离。

## 评估信号（发现即记）

- 无测试或测试很少（测试文件数 vs 源码比例失衡）
- 测试耦合外部（直连数据库/网络/真实文件系统）
- 无依赖注入、无法 mock（静态调用满天飞）
- 测试慢（集成测试当单元测试用，跑一次几分钟）
- 无测试覆盖率统计
- 私有方法直接测（破坏封装）
- 测试不稳定（flaky，时过时不过）

## 评估工具与命令

| 工具 | 命令/用法 | 看什么 |
|------|----------|--------|
| Glob | 测试文件数 vs 源码数 | 测试覆盖广度 |
| RunCommand | 跑测试套件 | 耗时、通过率、flaky |
| RunCommand | 跑覆盖率（jest --coverage/jacoco/go test -cover） | 覆盖率数值 |
| Grep | 查 mock/DI 框架引用 | 可测设计程度 |
| ast-grep | 静态调用模式 | 是否难 mock |

## 评分锚点（5 档判定）

| 分 | 锚点信号 |
|----|---------|
| 4 | 单元/集成/端到端分层清晰 + DI 充分 + 单测快(<10s) + 覆盖率 >80% + 外部依赖全 mock + 无 flaky |
| 3 | 有分层测试 + 覆盖率 50-80% + 部分耦合外部 + 偶有 flaky |
| 2 | 有测试但混杂 + 覆盖率 20-50% + 测依赖外部 + 测试慢 |
| 1 | 测试很少 + 覆盖率 <20% + 无分层 + 难 mock |
| 0 | 无测试（触发否决） |

## 规范基线（新项目应做/不做）

- ✅ 应：单元/集成/端到端分层 + DI 可 mock + 外部依赖隔离(testcontainers/fake) + 覆盖率门禁 + 快速单测 + 测关键路径契约
- ❌ 不做：直连真实数据库的单测 + 静态调用满天飞 + 集成测试当单测 + 私有方法测 + flaky 不修

## 对标要点（业界标杆看哪些）

- 看标杆项目的测试分层策略与目录结构
- 看其覆盖率门禁配置与数值
- 看其外部依赖隔离手段（testcontainers/fakes/mocks）

## 反模式

```
❌ 直连真实 DB 的"单元测试"（实际是慢集成测试）
❌ 静态调用满天飞（无法 mock）
❌ 覆盖率不统计或统计了不看
❌ flaky 测试重跑掩盖（根因不修）
❌ 测私有方法（破坏封装）
```

## Checklist

- [ ] 测试文件数 vs 源码比例是否合理
- [ ] 是否跑了覆盖率
- [ ] 单测是否快且不依赖外部
- [ ] 是否有 DI/可 mock 设计
- [ ] 是否有 flaky 测试
- [ ] 测试是否分层
